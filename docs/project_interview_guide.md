# 新闻智能助手项目面试介绍

## 一、项目定位

这是一个基于 FastAPI 的新闻智能助手系统，后端主要负责新闻数据管理、用户认证、收藏与浏览记录、AI 智能问答以及多会话管理。

系统采用异步分层架构，使用 MySQL 保存业务数据，Redis 负责新闻缓存和 RAG 问答缓存，LangChain 负责组织 Agent 和 RAG 流程，GPT 兼容 API 提供对话能力，ChromaDB 用于保存新闻向量。

整体调用链路如下：

```text
前端 Vue
   ↓
FastAPI 路由层
   ↓
业务 CRUD / Service 层
   ↓
MySQL + Redis + ChromaDB
   ↓
LangChain Agent / RAG + GPT
```

## 二、后端主要功能

### 1. 新闻模块

提供新闻分类、分页列表、新闻详情、相关推荐和浏览量统计等功能。

新闻列表和详情使用 Redis Cache-Aside 缓存策略：

```text
先查 Redis
  ↓
缓存命中，直接返回
  ↓
缓存未命中，查询 MySQL
  ↓
将查询结果写回 Redis
```

当新闻浏览量变化时，会主动删除对应详情缓存，避免缓存中的浏览量过期。

### 2. 用户与权限模块

实现用户注册、登录、Token 鉴权、个人资料修改、头像上传、密码修改和忘记密码重置。

登录后生成 UUID Token 并保存到 `user_token` 表，接口通过 FastAPI 依赖注入获取当前用户。密码使用 bcrypt 加密，不保存明文密码。

收藏、浏览记录、AI 对话历史等接口都要求登录后才能访问。

### 3. 收藏和浏览记录

用户可以收藏或取消收藏新闻，也可以查看和清空收藏列表。

收藏表使用以下唯一约束：

```text
user_id + news_id
```

避免同一用户重复收藏同一条新闻。

浏览记录保存用户、新闻和浏览时间，并提供分页查询、删除单条记录和清空记录功能。

### 4. AI Agent

AI Agent 基于 LangChain 的 OpenAI Tools Agent 实现，目前提供以下工具：

- 根据关键词搜索新闻
- 添加收藏
- 取消收藏
- 查看我的收藏
- 清空我的收藏

当用户说“帮我收藏某条新闻”或“清空我的收藏”时，模型会根据用户意图自动选择对应工具，而不是只返回文本。

为了保证工具能够识别当前登录用户，后端使用 `ContextVar` 在请求生命周期内传递用户 ID。流式响应的生成器在接口函数返回后才执行，因此用户 ID 的设置和重置必须放在生成器内部，否则工具会误判用户未登录。

### 5. AI 流式输出

普通问答接口使用 `/api/agent/chat`，流式问答接口使用：

```text
POST /api/agent/chat/stream
```

后端通过 LangChain 的 `astream_events(version="v2")` 监听模型事件，并通过 SSE 返回：

- AI 文本片段
- 工具调用状态
- Token 使用量
- 会话 ID
- 完成事件

前端可以在模型生成第一个文本片段时立即显示内容，不需要等待完整回答生成。

### 6. 多会话和上下文记忆

系统设计了以下两张表保存会话和消息：

```text
chat_session
chat_message
```

每个用户可以创建多个 AI 会话，系统会自动生成会话标题，并将最近的历史消息转换为 `HumanMessage` 和 `AIMessage`，注入 LangChain Prompt，实现多轮上下文记忆。

### 7. Token 消费限制

系统新增 `ai_usage` 表记录：

```text
prompt_tokens
completion_tokens
total_tokens
created_at
```

通过自定义 `TokenUsageHandler` 兼容不同 LLM 返回的 Token 使用格式，并按用户统计每日消耗。

当用户达到每日限制后，接口返回 HTTP 429，前端显示剩余额度。

### 8. RAG 检索

RAG 链路的设计如下：

```text
用户问题
  ↓
向量检索 / 关键词降级检索
  ↓
召回新闻内容
  ↓
拼接上下文
  ↓
GPT 生成答案
```

ChromaDB 作为向量检索组件。当外部 Embedding 服务不可用或向量集合为空时，系统会自动降级到 MySQL 标题和正文关键词检索，再交给 GPT 生成回答，避免整个问答接口不可用。

这种设计提高了系统的容错性。需要说明的是，向量检索是否生效依赖外部服务是否真正提供兼容的 `/embeddings` 接口。

### 9. 缓存设计

Redis 分为两个逻辑数据库：

```text
db 0：新闻分类、新闻列表、新闻详情等业务缓存
db 15：RAG 问答缓存
```

缓存层统一封装了 JSON 读写、删除和异常处理。当 Redis 不可用时，缓存异常会被记录日志，不直接阻塞主要业务请求。

### 10. 容器化部署

Docker Compose 编排以下服务：

- FastAPI 应用
- MySQL
- Redis

ChromaDB 以应用内持久化目录的形式运行，而不是独立容器。

Dockerfile 使用多阶段构建，分离依赖安装阶段和运行阶段，减少最终运行镜像内容。

## 三、前端部分

前端使用 Vue 3、Vite 和 Vant，主要实现：

- 新闻分类和分页浏览
- 新闻详情与相关推荐
- 登录注册
- 收藏和浏览记录
- AI 对话
- 多会话历史
- 个人资料编辑

面试时可以简单介绍前端，重点放在后端架构、AI Agent、RAG、缓存和鉴权设计上。

## 四、项目难点与解决方案

### 难点一：AI 工具调用中的用户身份传递

Agent 工具需要知道当前登录用户，才能正确执行收藏和清空收藏等操作。由于流式响应的异步生成器在接口函数返回后才开始消费，如果在外层设置用户上下文，生成器执行时上下文可能已经被重置。

解决方式是把 `ContextVar` 的设置和重置都放到流式生成器内部，保证工具执行期间可以读取正确的用户 ID。

### 难点二：AI 对话响应速度

普通接口需要等待模型生成完整答案后才能响应，用户体验较慢。

解决方式是使用 `astream_events(version="v2")` 监听模型输出事件，将文本片段通过 SSE 实时返回，实现首字响应和工具状态提示。

### 难点三：Embedding 服务异常导致 RAG 不可用

外部 GPT 兼容服务的 Embedding 接口可能不可用，或者向量集合还没有生成数据。如果 RAG 强依赖向量检索，整个问答接口会直接失败。

解决方式是增加降级策略：优先使用 ChromaDB 向量检索，向量库为空或 Embedding 请求失败时，使用 MySQL 对新闻标题和正文进行关键词检索，再由 GPT 根据召回内容生成答案。

### 难点四：缓存数据与实时数据不一致

新闻详情缓存中包含浏览量，浏览量更新后如果不清理缓存，前端会看到旧数据。

解决方式是在浏览量更新成功后主动删除对应新闻详情缓存，并将用户相关的收藏状态通过独立接口查询，避免把用户状态混入公共新闻列表缓存。

### 难点五：AI Token 消费控制

AI 接口调用次数增加后，需要防止单个用户无限消耗模型资源。

解决方式是通过回调捕获模型返回的 Token 使用量，保存到 `ai_usage` 表，按用户和日期统计消耗，并在调用前检查每日额度，超过额度后返回 429。

## 五、面试口述版本

我做的是一个基于 FastAPI 的新闻智能助手系统。后端采用分层架构，使用异步 SQLAlchemy 操作 MySQL，Redis 负责新闻和问答缓存，LangChain 负责 Agent 工具调用和 RAG 链路。系统实现了新闻浏览、用户认证、收藏、浏览历史以及 AI 对话等功能。

AI 部分支持普通问答和 SSE 流式输出，用户可以通过自然语言搜索新闻、收藏新闻或清空收藏。项目还设计了多会话历史和每日 Token 限额，通过自定义回调统计模型消耗。

RAG 优先使用 ChromaDB 检索新闻向量，当 Embedding 服务不可用时自动降级到 MySQL 关键词检索，保证系统仍然可以基于新闻内容回答问题。项目中比较有挑战的部分是流式响应中的用户身份传递、Agent 工具调用、缓存失效以及 AI 服务异常时的降级处理。

## 六、开发测试中遇到的问题及解决方案

下面的问题都来自项目实际开发和联调过程，面试时可以按照“现象 → 原因 → 解决方案 → 结果”的结构回答。

### 问题一：MySQL 创建 AI 用量表时出现外键类型不兼容

**面试官：** 创建 `ai_usage` 表时遇到过什么数据库问题？

**回答：**

项目启动时 MySQL 报错：`Referencing column 'user_id' and referenced column 'id' are incompatible`。排查后发现 `user.id` 是 `int unsigned`，而新建的 `ai_usage.user_id` 是普通 `int`。MySQL 要求外键字段和被引用字段的类型、符号属性完全一致。

解决时使用 SQLAlchemy 的 MySQL 方言类型：

```python
from sqlalchemy.dialects.mysql import INTEGER

user_id = mapped_column(
    INTEGER(unsigned=True),
    ForeignKey("user.id")
)
```

同时通过 `information_schema` 检查数据库中的真实字段类型，而不是只看 ORM 模型。这个问题让我意识到，数据库迁移时必须同时核对 ORM 定义和已有数据库结构。

### 问题二：`create_all()` 没有修复已有表结构

**面试官：** 为什么修改了 ORM 模型后，数据库表仍然没有变化？

**回答：**

`Base.metadata.create_all()` 只负责创建不存在的表，不会自动给已有表增加字段、修改字段类型或删除字段。因此对于已经存在的数据库，需要单独编写迁移逻辑，先查询 `information_schema`，再执行 `ALTER TABLE`，或者使用 Alembic 管理正式迁移。

### 问题三：Redis 连接被拒绝

**面试官：** Redis 出现 `Connection refused` 时是怎么处理的？

**回答：**

日志显示应用连接 `127.0.0.1:6379` 失败。先检查 Redis 服务是否启动，再检查端口监听状态。项目使用 Docker Redis 容器，启动后通过 `redis-cli ping` 或 Python Redis 客户端验证连接。

另外，缓存层没有让 Redis 异常直接导致新闻接口失败。`get_cache()` 等函数捕获连接异常并返回空值，业务层会回源 MySQL，这样 Redis 短暂不可用时系统仍能提供基本功能。

### 问题四：在项目根目录执行 `npm run dev` 报错

**面试官：** 前端启动时遇到过什么问题？

**回答：**

项目的 `package.json` 位于 `frontend` 目录，而不是仓库根目录。在根目录执行 `npm run dev` 会报 `ENOENT: package.json not found`。

正确启动方式是：

```powershell
cd frontend
npm run dev
```

同时在 Vite 中配置 `/api` 代理到 FastAPI 的 8000 端口，避免前端直接处理跨域地址。

### 问题五：前端出现白屏或动态模块加载失败

**面试官：** Vue 页面白屏时如何定位？

**回答：**

先查看浏览器控制台和 Vite 日志，发现过 `Failed to fetch dynamically imported module`。原因是修改 Vite 配置后，旧的依赖预构建缓存仍然引用旧文件哈希。

解决方式是停止前端服务，删除：

```text
frontend/node_modules/.vite
```

然后重新执行 `npm run dev`。另外，项目使用了 Vant 的 `v-lazy` 指令，需要在 `main.js` 中显式注册 `Lazyload`，否则会出现指令解析警告。

### 问题六：新闻图片无法加载

**面试官：** 图片显示异常时是如何排查的？

**回答：**

一部分图片依赖外部图片 CDN，在网络环境下加载不稳定。后来将新闻图片下载到后端的 `backend/static/images` 目录，并由 FastAPI 挂载 `/static` 静态资源。

由于前端页面运行在 5173 端口，绝对路径 `/static/images/...` 默认会请求 Vite，而不是 FastAPI，所以又在 Vite 中增加了 `/static` 代理到 8000 端口。

### 问题七：下拉分页一直显示“加载中”

**面试官：** 分页加载卡住的原因是什么？

**回答：**

Vant 的 `van-list` 在触底时会先把自身的 `loading` 设为 `true`，然后才触发 `load` 事件。如果业务函数一进入就判断 `loading === true` 并直接返回，就会形成互锁，后续请求永远不会发送。

解决方式是业务层只判断 `finished`，由 `finally` 统一恢复 `loading`，并将首次加载和触底加载统一包装，避免两个加载流程互相竞争。

### 问题八：相关推荐点击后页面内容没有变化

**面试官：** Vue 路由跳转到另一条新闻时为什么组件没有刷新？

**回答：**

两个地址都使用 `/news/:id`，Vue Router 会复用同一个组件实例，因此只执行一次 `onMounted`，路由参数变化后不会重新请求数据。

解决方式是把详情加载逻辑抽成 `loadDetail()`，同时监听：

```javascript
watch(() => route.params.id, loadDetail)
```

这样新闻 ID 变化时会重新加载详情、相关推荐、收藏状态和浏览记录。

### 问题九：登录失败没有提示，登录页被错误跳转

**面试官：** 登录和 Token 鉴权遇到过什么问题？

**回答：**

前端最初只判断本地是否存在 Token，没有验证 Token 是否仍然有效，导致失效 Token 也会被当成已登录状态。解决方式是在进入登录页或注册页时调用 `/api/users/info` 验证 Token，验证失败就清理本地登录信息。

另外，后端统一返回 `{code, message, data}`，而前端最初只读取 Axios 的 `detail` 字段，所以登录失败时没有提示。后来在响应拦截器中兼容读取 `message` 和 `detail`，并单独处理登录接口自身的 401，确保错误信息能显示给用户。

### 问题十：只修改昵称时数据库没有更新

**面试官：** 编辑资料时为什么只改昵称也可能保存失败？

**回答：**

前端会提交完整表单，其中未填写的手机号可能是空字符串。数据库中的 `phone` 字段有唯一约束，多个用户保存空字符串会触发唯一索引冲突，整个事务回滚。

后端在 `crud/users.py` 中将空字符串转换为 `None`，让数据库保存 `NULL`：

```python
data = {
    key: None if value == "" else value
    for key, value in data.items()
}
```

同时补全 `UserInfoResponse`，让更新接口返回昵称、头像、性别、简介和手机号。这样既解决了数据库更新失败，也解决了“数据库已更新但前端看起来没有变化”的问题。

### 问题十一：AI 认为用户没有登录，无法清空收藏

**面试官：** Agent 工具调用时如何保证用户身份正确？

**回答：**

普通接口中可以直接读取当前用户，但流式接口返回 `StreamingResponse` 后，异步生成器是在接口函数返回之后才真正执行的。最初把 `ContextVar` 放在外层函数中设置，并在返回前重置，导致工具执行时拿到默认用户 ID `0`，于是误判为未登录。

解决方式是把 `current_user_id_var.set(user.id)` 和 `reset()` 都放到 `event_generator()` 内部的 `try/finally` 中，保证工具执行的整个生命周期内都能获取当前用户 ID。

### 问题十二：流式接口没有 Token 输出或拿不到用量

**面试官：** LangChain 流式输出过程中遇到过什么兼容性问题？

**回答：**

最初使用 `astream()`，它更接近事件或结果粒度，不一定能实现逐 Token 输出。后来改用 `astream_events(version="v2")`，监听 `on_chat_model_stream` 获取文本片段，监听 `on_tool_start` 显示工具状态。

同时发现 `version="v1"` 下的结束事件通常是 `LLMResult`，不容易直接拿到模型的 `usage_metadata`。因此改用 v2，并在 `on_chat_model_end` 中累计 `input_tokens` 和 `output_tokens`。工具循环可能触发多次模型调用，所以不能只记录最后一次用量。

### 问题十三：AI 总结新闻时只有标题，没有正文内容

**面试官：** 为什么 AI 能找到新闻，却不能总结？

**回答：**

最初的搜索工具只返回新闻 ID 和标题，模型没有正文上下文，因此只能重复标题或要求用户继续操作。

解决方式是让搜索工具同时返回新闻正文摘要，并在系统提示词中明确：用户要求总结时，必须依据工具返回的“内容”字段直接总结，不要只复述标题。新闻推荐结果还统一输出 `/news/{id}` 链接，方便前端跳转详情页。

### 问题十四：Embedding 服务返回 503，RAG 无法检索

**面试官：** RAG 调试时遇到过什么外部服务问题？

**回答：**

项目使用的 GPT 兼容服务模型列表中没有 Embedding 模型，调用 `gpt-5.6-luna` 的 `/embeddings` 接口返回 503。同时 ChromaDB 中对应集合的文档数量为 0，所以 RAG 没有可检索内容。

排查时先检查模型列表、Embedding 请求和 ChromaDB 集合数量，而不是直接判断是业务代码错误。最终在 RAG 中增加降级策略：优先使用 ChromaDB，向量库为空或 Embedding 服务异常时，改用 MySQL 对新闻标题和正文进行关键词检索，再将召回内容交给 GPT 生成答案。这样即使外部 Embedding 服务不可用，RAG 接口仍能返回基于新闻数据的回答。

### 问题十五：向量重建脚本无法导入项目模块

**面试官：** 执行向量构建脚本时遇到过什么 Python 工程问题？

**回答：**

直接执行脚本时，Python 默认只把脚本所在目录加入模块搜索路径，后端的 `config` 等模块可能无法导入。现在脚本会主动加入 `backend` 目录，因此可以从项目根目录直接执行：

```powershell
python backend/scripts/build_vectors.py
```

这也更符合 Python 包的运行方式，能够保证项目内部绝对导入正常工作。

## 七、面试回答总结方法

遇到类似问题时，不要只说“我改了代码”。可以按照下面的顺序回答：

1. 先说明用户看到的现象或错误日志。
2. 说明如何缩小范围，例如检查请求、日志、数据库结构、缓存状态或外部接口。
3. 解释最终根因，而不是只描述表面现象。
4. 说明具体解决方式，以及为什么选择这种方案。
5. 最后说明如何验证，例如接口回归、数据库查询、浏览器走查或异常场景测试。
